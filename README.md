# Yasawi Startup

Платформа YASAWI STARTUP состоит из публичного сайта на Next.js и CMS/API на NestJS. Контент, программы, потоки, проекты, партнёры, команда, новости и заявки хранятся в PostgreSQL и управляются через админ-панель.

## Что уже управляется из админ-панели

- контакты, социальные сети, цифры и тексты первого экрана;
- программы, сроки набора, длительность, вместимость и статус приёма;
- отдельные потоки программ;
- проекты, теги, этап, ссылки, порядок показа и публикация;
- обложки и галерея проектов;
- партнёры и их логотипы;
- заявки, статусы, заметки, история обработки и CSV-экспорт;
- новости с автоматической синхронизацией AYU и команда, которая ведётся вручную;
- смысловые переводы контента на русский, казахский, английский и турецкий языки;
- администраторы, роли и журнал изменений.

## Локальный запуск

Потребуются Node.js 20+ и PostgreSQL 17+. Для базы можно использовать установленный PostgreSQL или Docker.

1. Установите зависимости:

   ```bash
   npm install
   ```

2. Скопируйте `.env.example` в `.env` и обязательно задайте собственные значения:

   ```env
   DATABASE_URL=postgresql://yasawi:strong-password@localhost:5432/yasawi_startup?schema=public
   JWT_ACCESS_SECRET=long-random-secret-at-least-32-characters
   ADMIN_SEED_EMAIL=admin@example.kz
   ADMIN_SEED_PASSWORD=another-strong-password
   ```

3. Если используется Docker, запустите PostgreSQL:

   ```bash
   docker compose up -d postgres
   ```

4. Примените миграции и создайте начальные данные:

   ```bash
   npm run db:deploy
   npm run db:seed
   ```

5. В двух терминалах запустите API и сайт:

   ```bash
   npm run dev:api
   npm run dev:web
   ```

Адреса после запуска:

- сайт — `http://localhost:3000`;
- админ-панель — `http://localhost:3000/admin`;
- API — `http://localhost:4000/api`;
- Swagger — `http://localhost:4000/api/docs`;
- проверка сервиса и базы — `http://localhost:4000/api/health`.

В админ-панель нужно войти через `ADMIN_SEED_EMAIL` и `ADMIN_SEED_PASSWORD`. После первого production-запуска пароль следует заменить и удалить `ADMIN_SEED_PASSWORD` из постоянной конфигурации, если повторный seed больше не нужен.

## Команды

```bash
npm run typecheck       # проверка TypeScript во всём проекте
npm run build           # production-сборка API и сайта
npm run db:migrate      # создать миграцию при изменении схемы
npm run db:deploy       # применить готовые миграции
npm run db:seed         # начальное наполнение/перенос старого JSON
npm run db:studio       # визуальный просмотр PostgreSQL
npm run test:smoke      # короткая проверка уже запущенного API
npm run test:contracts  # проверка контрактов форм админки через Next /api
npm run test:news-sync  # контракты импорта новостей и fallback-кэша
npm run test:security   # проверка production-конфигурации безопасности
npm run test:text-integrity # проверка UTF-8 в исходниках и данных публичного API
npm run test:integrations   # проверка SMTP-статуса и локального медиахранилища
```

Для smoke-теста задайте `TEST_ADMIN_EMAIL` и `TEST_ADMIN_PASSWORD`; адрес API можно изменить через `TEST_API_URL`.

## Автоматизация AYU

API периодически синхронизирует новости с официальной страницы AYU. Результат сохраняется в PostgreSQL, поэтому публичный сайт не зависит от скорости внешнего сайта. В админ-панели синхронизацию можно запустить вручную, а отредактированные вручную записи не перезаписываются автоматически. Состав команды не парсится и полностью ведётся администраторами.

Источник новостей задаётся через `AYU_NEWS_SOURCE_URL`.

## Локализация

Публичный сайт поддерживает `ru`, `kk`, `en` и `tr`. Выбор языка сохраняется в cookie `yasawi_locale`, а публичные API принимают параметр `?locale=kk|ru|en|tr`. Русский является базовым языком и используется как безопасный fallback.

В PostgreSQL локализуемые сущности содержат поле `translations` в формате JSON:

```json
{
  "kk": { "title": "Қазақша атау", "description": "..." },
  "en": { "title": "English title", "description": "..." },
  "tr": { "title": "Türkçe başlık", "description": "..." }
}
```

Редактирование доступно в админ-панели в разделе «Переводы» для главной, программ, IT-курсов, проектов, команды, новостей и CMS-страниц. Язык каждой новой заявки также сохраняется в базе и попадает в CSV-экспорт.

## Файлы и изображения

Локально загруженные изображения сохраняются в `apps/api/uploads` и автоматически конвертируются в WebP. Для production рекомендуется заполнить S3-переменные из `.env.example`, чтобы файлы хранились в S3-совместимом объектном хранилище.

## Почта и медиахранилище

Состояние интеграций видно в админ-панели в разделе «Сервисы». Администратор может отдельно проверить SMTP и хранилище без отправки тестовой заявки.

Для почтовых уведомлений заполните `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASSWORD` и `SMTP_FROM`. После получения заявки система отправляет подтверждение заявителю и уведомление на контактный email из настроек сайта. Ошибка почтового провайдера не отменяет сохранённую заявку и фиксируется в журнале API.

Без S3 изображения сохраняются в `MEDIA_ROOT`; эта папка должна находиться на постоянном диске сервера. Для S3-совместимого хранилища заполните `S3_BUCKET`, `S3_REGION`, `S3_ENDPOINT`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` и `S3_PUBLIC_URL`. В production-шаблоне `REQUIRE_SMTP=true` и `REQUIRE_S3=true` не позволяют запустить API с незаполненной обязательной интеграцией.

## Перед публикацией

- используйте отдельную production-базу и выполните `npm run db:deploy`;
- задайте длинные уникальные `JWT_ACCESS_SECRET`, пароль БД и пароль администратора;
- для production обязательно используйте HTTPS, `COOKIE_SECURE=true`, уникальный `IP_HASH_SALT` длиной от 32 символов и точный HTTPS-домен в `WEB_ORIGIN`;
- Swagger в production отключён по умолчанию; включайте `SWAGGER_ENABLED=true` только на ограниченное время;
- при запуске production API проверяет окружение и фактические пароли активных администраторов, поэтому известный тестовый пароль заблокирует запуск;
- настройте SMTP для писем по заявкам и S3 для постоянного хранения медиа;
- включите резервные копии PostgreSQL и объектного хранилища;
- выполните и подпишите организационные пункты из `docs/legal/production-compliance.md`; публичные тексты политики, согласия и условий должны быть утверждены Университетом;
- основную базу персональных данных, резервные копии и журналы размещайте на территории Республики Казахстан; проверьте страны обработки SMTP, S3 и других поставщиков;
- выполните `npm run typecheck`, `npm run build` и проверку зависимостей перед деплоем.

Старый `apps/api/data/db.json` читается seed-скриптом только как источник миграции. Рабочие данные после перехода хранятся в PostgreSQL.
